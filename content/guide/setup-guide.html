From nothing installed to a running site you can direct.

Every download, every command, and what each one is actually for. Written for a designer who has never opened a terminal. By the end, you'll have your own copy of this portfolio running at localhost:3000 with Claude Code sitting next to it, waiting for instructions.

macOS · about 60–90 minutes · check things off as you go; progress is saved in this browser.

00Read this first

You are not learning to code this week. You are learning to run a small, modern web project on your own machine so that an AI agent can build inside it while you watch, judge, and direct. The setup below is the same setup a front-end engineer at any product company would have. That's the point: your portfolio won't be a template someone else designed. It'll be a real codebase you own. The starter Vinson made is a skeleton with placeholder words and a placeholder look; every visual decision on it is still yours to make.

There are three ideas that make everything else make sense:

  1. Apps you install once (VS Code, Node, Git) vs. packages that live inside each project (everything npm downloads). Section 01.
  2. The terminal is just a text box that runs commands inside a folder. Section 03.
  3. The dev server is what shows you your site live while it changes. Section 06.
House rule

You type every command yourself. Vinson can sit next to you and tell you what to type, but his hands stay off your keyboard. Watching someone else do this teaches you nothing; doing it once badly teaches you everything.

01Two kinds of “download”

You'll download things two different ways this week, and confusing them is the number one source of “wait, where did that go?”

Apps from the web

  • VS Code, Node.js, Git, Chrome
  • Download from a website, run an installer
  • Install once for the whole Mac
  • Live in /Applications or system folders
  • You'll almost never touch these again

Packages from npm

  • Next.js, React, Tailwind, TanStack Query
  • Downloaded by typing a command in the terminal
  • Installed per project, into the project folder
  • Live in a folder called node_modules
  • Listed in package.json so they can be re-downloaded anytime

Think of it like Figma vs. a Figma file's fonts and plugins. Figma is installed once. The specific fonts a file uses belong to that file. npm packages are the fonts and plugins; Node is Figma.

02Install the apps

Four installs and two accounts. Do them in this order; later ones assume earlier ones.

VS Code

The editor. Files on the left, code in the middle, terminal at the bottom, Claude on the right. Everything this week happens inside this one window.

  1. Go to code.visualstudio.com and click Download for macOS. It's one universal build for Apple Silicon and Intel.
  2. Open the downloaded .zip. It unpacks to Visual Studio Code.app.
  3. Drag that app into your Applications folder. (If you skip this, macOS keeps it in Downloads and it behaves weirdly later.)
  4. Open it. If macOS asks whether you're sure, say yes.
  5. Press ⌘⇧P, type shell command, and choose Shell Command: Install 'code' command in PATH. This lets you type code . in a terminal to open a folder in VS Code. You'll use it constantly.

Node.js

The engine that runs JavaScript outside a browser. Next.js needs it to run your site locally, and installing Node also installs npm, the tool that downloads packages. You never “open” Node. It just needs to exist.

  1. Go to nodejs.org.
  2. Download the LTS version (currently v24; “LTS” means long-term support, the stable one). Pick the macOS Installer (.pkg).
  3. Open the .pkg and click through: Continue, Agree, Install. It'll ask for your Mac password.
  4. When it says the install was successful, close it. That's it.

Video walkthrough if you want to see it done: How To Install Node.js on Mac. Any version of Node 20.9 or newer works for Next.js; LTS is the right pick.

If you already had a terminal window open before installing Node, close it and open a new one. Terminals only learn about new programs when they start.

Git

Version history for your project. Every “save point” you make is a commit; pushing those commits to GitHub is what triggers your site to deploy. On a Mac, Git comes with Apple's developer tools, so the install is a one-liner.

  1. Open the Terminal app (press ⌘Space, type terminal, hit return). Just this once; from Section 03 onward you'll use the terminal inside VS Code.
  2. Type git --version and press return.
  3. If a version prints, you're done. If a dialog pops up saying the command line developer tools need to be installed, click Install. It takes a few minutes. Then run git --version again.
  4. Tell Git who you are. Use the same email you'll use for GitHub:
Terminal
% git config --global user.name "Your Name"
% git config --global user.email "you@example.com"

Claude Code, the VS Code extension

This is the builder. It's a panel inside VS Code where you describe what you want, and it edits the files in your project. It's the same engine as the terminal version of Claude Code, with a graphical interface: you see diffs before they're applied, you can rewind, you can drag screenshots in.

  1. You need a paid Claude account (Pro or Max). Sign up at claude.ai first if you don't have one. The extension signs in with that account; no API key, no billing setup.
  2. In VS Code, press ⌘⇧X to open the Extensions view.
  3. Search for Claude Code. The publisher is Anthropic. Click Install.
  4. Look for the ✱ spark icon: in the top-right of the editor when a file is open, and in the left Activity Bar always. Click it.
  5. Click Sign in. Your browser opens; approve it; come back to VS Code. A Learn Claude Code checklist appears. Worth clicking through once.

The extension bundles its own copy of Claude Code. You do not need to install anything else for the panel to work. Typing claude in the terminal is a separate install (the CLI) and is deliberately not part of this week. Section 08 explains when that becomes worth it.

Two accounts: GitHub and Vercel

GitHub is where the code lives online. Vercel is the host that turns that code into a public website, automatically, every time you push.

  1. github.com → sign up. Use a username you'd put on a résumé; it's public.
  2. vercel.com → Continue with GitHub. Don't make a separate password; linking the two is the whole point.

You won't use either of these until Section 09. Make them now so nothing blocks you later.

Check that it all worked

Open VS Code, open its terminal (next section explains how; for now: ⌃`), and type each line. Each should print a version number, not command not found.

zsh
% node -v
v24.20.0
% npm -v
11.6.2
% git --version
git version 2.50.1
% code --version
1.104.0
# your numbers will differ. any number is a pass.

03The terminal

A terminal is a text box. You type a command, press return, and the computer does the thing and prints what happened. That's all it is. It feels hostile because it doesn't explain itself, but it never does anything you didn't type.

Open it inside VS Code

Press ⌃`. That's Control (the key labeled control, not Command) plus the backtick key, which is the one directly under esc on a Mac keyboard. Press it again to hide the terminal. ⌃⇧` opens a second terminal beside the first.

If the shortcut doesn't fire, use the menu: Terminal → New Terminal.

Why VS Code's terminal and not the Terminal app: VS Code's terminal opens already inside the folder you have open. Commands act on whatever folder you're “in,” so this saves you from the most common beginner problem, which is running a command in the wrong place.

Read the prompt

The line waiting for you looks something like this:

zsh
alex@Alexs-MacBook-Air portfolio % ▍

Your username, your computer's name, and then the folder you're currently in (portfolio), then a %. Everything after the % is what you type. The folder name is the important part: it tells you where commands will run.

The seven things you'll actually do

TypeWhat it does
pwdPrint the full path of the folder you're in. “Where am I?”
lsList what's in this folder.
cd portfolioMove into the folder called portfolio. cd .. moves up one level.
clearWipe the screen. Changes nothing.
⌃CStop whatever is running. This is how you stop the dev server.
↑Bring back the last command you typed. Press again for older ones.
TabAutocomplete a folder or file name. Type cd por, hit Tab, get cd portfolio/.

Copy and paste work normally (⌘C / ⌘V). Every code block in this guide has a Copy button; paste it into the terminal and press return.

Two rules. Never paste a command you don't understand from a random website; ask Claude or Vinson what it does first. And if a command asks for your password, that's sudo, and you almost certainly don't need it this week. Stop and ask.

04npm

npm is an app store for code, without the storefront. Instead of clicking Install you type npm install something, and it downloads that package into your project. Every modern web project is assembled from hundreds of these packages; Next.js is one, React is one, Tailwind is one.

The two files that matter

package.json is the shopping list. It names your project, lists the packages it depends on, and defines named scripts (shortcuts like dev and build). It's small, human-readable, and gets committed to Git.

node_modules/ is the delivered boxes. It's where npm actually puts the downloaded code. It's enormous (tens of thousands of files), it's automatically excluded from Git, and you never edit anything in it. If it gets weird, delete the whole folder and run npm install; it comes back identical.

The four commands

CommandMeaning
npm installDownload everything on the shopping list. Run this after cloning a project or when someone says “did you install?”
npm install @tanstack/react-queryAdd one package to the list and download it.
npx create-next-app@latestRun a tool once without keeping it. npx fetches the tool, runs it, done. (This is the tool that made the template you're about to download.)
npm run devRun the script named dev from package.json. Same for npm run build.

The line in the terminal after npm install that says “added 340 packages” is normal. So is a wall of text. Read the last two lines; that's where problems show up.

05Get the project

You are not starting from a blank folder. Vinson built a template repository: the site's skeleton, the design tokens, one sample case study, and this guide. You make your own copy of it on GitHub, download that copy to your Mac, and install its packages. Three steps, then you never think about it again.

Decide where it lives

Make a Projects folder in your home directory and work inside it. Not Desktop, not Downloads, not iCloud Drive (iCloud syncing node_modules will make your Mac miserable).

zsh
% mkdir -p ~/Projects
% cd ~/Projects
# ~ means your home folder. mkdir makes a folder. cd moves into it.

Make your own copy on GitHub

  1. Open the template: {{TEMPLATE_REPO_LABEL}}. Sign in to GitHub if it asks.
  2. Click the green Use this template button, then Create a new repository.
  3. Owner: you. Repository name: portfolio. Public or private, either works. Click Create repository.
  4. You now have github.com/your-username/portfolio. It has one commit, and it's entirely yours.

Why not fork or clone Vinson's repo directly? A fork stays tied to his; a plain clone of his repo gives you nowhere to push. Use this template gives you a fresh repository with a clean history that belongs to you, which is what Vercel needs in Section 09.

Download it to your Mac (this is called cloning)

Do this from inside VS Code the first time, so VS Code handles the GitHub sign-in for you and you never have to deal with tokens.

  1. Open VS Code. Press ⌘⇧P, type git clone, choose Git: Clone.
  2. Choose Clone from GitHub. A browser window asks you to authorize VS Code. Approve it and come back.
  3. Type portfolio and pick your-username/portfolio from the list.
  4. When it asks where to put it, pick the Projects folder you just made. Click Select as Repository Destination.
  5. VS Code asks Would you like to open the cloned repository? Click Open. If it asks whether you trust the authors, click Yes, I trust the authors. You are the author now.

The same thing, as a terminal command, for next time or for a second computer:

zsh · ~/Projects
% git clone https://github.com/YOUR-USERNAME/portfolio.git
Cloning into 'portfolio'...
% cd portfolio
% code .
# "code" = VS Code, "." = this folder. A new VS Code window opens on the project.

From here on, do everything in that VS Code window. Open its terminal with ⌃` and notice the prompt already says portfolio.

Install the packages

The repo has the shopping list (package.json) but not the boxes (node_modules); Git never stores those. One command downloads them.

zsh · portfolio
% npm install
added 400 packages, and audited 401 packages in 25s
found 0 vulnerabilities
# the numbers will differ. a wall of text is normal. read the last two lines.

A node_modules folder appears in the file tree. That's the delivered boxes. You never open it.

Add TanStack Query

One more package, and your first time adding one yourself. You won't use it until you build an interactive prototype that fetches data, but adding it now means Claude can reach for it when the time comes.

zsh · portfolio
% npm install @tanstack/react-query
added 3 packages in 2s

Open package.json in the file tree. You'll see @tanstack/react-query now listed under dependencies. That's the shopping list updating itself.

06Run it

A Next.js project has three modes, and each is one npm script. You'll live in the first one.

npm run dev — the dev server

Starts a tiny web server on your Mac that serves your site and rebuilds it every time you save a file. This is the thing that makes vibe coding work: Claude edits, you save (or it saves), the browser updates within a second.

zsh · portfolio
% npm run dev

  ▲ Next.js 16.3.4 (Turbopack)
  - Local:        http://localhost:3000
  - Network:      http://192.168.1.24:3000

 ✓ Ready in 900ms
  1. ⌘-click http://localhost:3000 in the terminal, or type it into Chrome. You'll see the portfolio homepage with a placeholder name on it. That placeholder is the first thing you'll replace.
  2. In VS Code, open content/site.ts. Change the tagline text, press ⌘S. Look at the browser. That's the loop.
  3. The terminal now looks “stuck.” It isn't; the server is running and waiting. Leave it. Open a second terminal with ⌃⇧` for other commands.
  4. To stop it: click in that terminal and press ⌃C. To start again: ↑ then return.

localhost means “this computer.” 3000 is the port, a numbered door. Nobody else can see it; it's your private preview. The Network line lets a phone on the same Wi-Fi see it, which is how you'll check mobile without deploying.

npm run build — the production build

Compiles the whole site into its final, optimized form: the exact thing Vercel will serve to the public. It also refuses to complete if anything is broken, which makes it your pre-flight check.

zsh · portfolio
% npm run build
  ▲ Next.js 16.3.4 (Turbopack)

  Creating an optimized production build ...
 ✓ Compiled successfully

 Route (app)                    Size   First Load JS
 ┌ ○ /                        5.2 kB        102 kB
 └ ○ /_not-found                0 B          97 kB

 ○  (Static)  prerendered as static content

Run this before every push you'd show someone. If it ends in red, the site is broken and Vercel's deploy will fail too. Copy the error, paste it to Claude, fix, build again. Green build → safe to push.

The table it prints is real information: every page of your site and how much code the browser has to download to show it. When a case-study page balloons because of a huge image, you'll see it here first.

npm run start — preview the build

Serves the output of npm run build exactly as production would, at the same localhost:3000. No hot-reloading, no dev overlays. Use it rarely, when something behaves differently on Vercel than it did in dev. Stop it with ⌃C and go back to npm run dev.

Where these come from

Open package.json. The scripts block is the menu. npm run <name> runs the line next to that name. That's the entire mechanism.

package.json
"scripts": {
  "dev":   "next dev",
  "build": "next build",
  "start": "next start",
  "lint":  "eslint"
}

07What's in the folder

This is the part Squarespace hides from you. It's also the part that makes you employable: the ability to look at a modern project and know where things go. Here's what's in the template, and what each piece is for.

portfolio/ ├── app/ ← your pages. every folder here is a URL │ ├── layout.tsx ← the frame around every page: fonts, header, footer │ ├── page.tsx ← the homepage. what shows at / │ ├── globals.css ← design tokens (colors, type scale) + the Tailwind import │ ├── about/page.tsx ← /about │ ├── work/page.tsx ← /work, the index of case studies │ ├── work/[slug]/page.tsx ← one case study. [slug] = a file name in content/work/ │ └── guide/page.tsx ← this guide. delete the folder when you're done with it ├── components/ ← reusable pieces: header, footer, case-study sections, slide deck ├── content/ ← YOUR WORDS. the folder you'll edit most │ ├── site.ts ← your name, role, email, links │ ├── about.mdx ← the about page │ └── work/ ← one .mdx file per case study. add a file, get a page │ ├── portfolio-crash-course.mdx ← the sample. delete it when you have real ones │ └── _TEMPLATE.mdx ← copy this to start a new case study ├── lib/ ← code that reads content/ and turns it into pages ├── public/ ← images and files served as-is. public/me.jpg → /me.jpg ├── docs/ ← Vinson's notes on how the template was built ├── node_modules/ ← downloaded packages. never edit, never commit ├── .next/ ← build output, appears after you run. ignore it ├── package.json ← the shopping list + scripts ├── package-lock.json ← exact versions of everything. don't touch, do commit ├── next.config.ts ← Next.js settings. mostly empty ├── tsconfig.json ← TypeScript settings. leave it ├── postcss.config.mjs ← wires Tailwind in. leave it ├── eslint.config.mjs ← code-quality rules. leave it ├── .gitignore ← tells Git to skip node_modules and .next ├── AGENTS.md ← rules for AI agents working in this repo ├── CLAUDE.md ← what Claude Code reads first. your design system, in words └── README.md

How a URL becomes a file

This is called file-based routing and it's the single most useful thing to understand. You don't configure URLs anywhere. You make a folder inside app/ with a page.tsx in it, and that folder's name is the URL. Case studies go one step further: app/work/[slug]/page.tsx is a single page that reads content/work/, so every .mdx file you add there becomes its own URL with no code change.

app/page.tsx→yoursite.com/ app/about/page.tsx→yoursite.com/about app/work/page.tsx→yoursite.com/work content/work/onboarding-redesign.mdx→yoursite.com/work/onboarding-redesign

layout.tsx wraps every page beneath it. The root one in app/ is where your nav, footer, and fonts go once, so every page gets them. When you tell Claude “add a nav,” it goes there.

Components: Figma components, but real

A component is a reusable piece of UI: a project card, a button, the case-study hero. They live in the components/ folder; the header, footer, case-study sections, and slide deck are already there. A page is just a layout of components with content dropped in. If you've built a Figma library, you already think this way.

Styling: Tailwind

Tailwind is CSS as class names, written directly on the element: class="text-lg font-semibold text-neutral-900". It looks noisy at first. The reason it's the standard for agent-built sites is that every style is visible right where it's used, so Claude can read and change it without hunting through separate CSS files. Your design tokens (type scale, spacing, colors) get declared once in globals.css and referenced everywhere.

How it ships

your filesapp/, components/, public/
→
git pushto GitHub
→
Vercel runs npm run buildsame command you ran
→
live siteon a global CDN, ~60 seconds

There's no “upload” step and no FTP. Push to GitHub is the deploy. That's the modern architecture in one sentence: source of truth in Git, hosting that rebuilds from it automatically.

08Claude Code in VS Code

The panel is where you'll spend most of the week. Here's how to work it well.

Open it and set the mode

  1. Click the ✱ spark icon (top-right of the editor with a file open, or in the left Activity Bar). Or press ⌘Esc, which toggles focus between your code and Claude's prompt box.
  2. At the bottom of the prompt box is a permission mode indicator. On Pro and Max it starts in Auto, where Claude applies most edits without asking. Click it and switch to Manual for this week.

In Manual mode, every edit shows you a side-by-side diff and asks before applying. That's slower and it's exactly what you want while learning: you see every change, you can reject it, and you start recognizing what the code for “a card grid” looks like. Switch to Auto in a couple of weeks once the diffs stop being interesting.

Give it what to look at

  • @-mention files. Type @ and a file name (@page.tsx) and Claude reads it. Fuzzy matching works; partial names are fine.
  • Select code, press ⌥K. Inserts a reference to exactly those lines. “Make @page.tsx#12-30 a 3-column grid on desktop.”
  • Hold ⇧ and drag files into the prompt box to attach them. This is how you hand Claude a Figma export or a screenshot of what's wrong. Do this constantly. A screenshot beats three sentences.
  • Type / for the command menu: attach files, switch model, toggle extended thinking, manage plugins.

Undo with rewind

Hover over any message in the conversation and a rewind button appears. Rewind code to here puts every file back the way it was at that point. This is your safety net before you're fluent with Git. Try it once on purpose so you trust it.

The Session history button at the top of the panel lists past conversations; click one to resume it with full context.

Your first prompt

With npm run dev running in the terminal and localhost:3000 open in Chrome, type this into Claude (fill in the brackets) and watch the browser:

Claude Code
Read CLAUDE.md first. Then open content/site.ts and replace the
placeholder name, role, tagline, and email with mine:
[your name], [your role], [one line about what you do], [your email].
Don't touch anything else. Tell me which files you changed.

You'll get a diff. Read it, even if you don't understand all of it. Accept. Look at the browser: the header and the hero now say your name. That's the loop from the deck; you just ran it once.

Extension now, terminal version later

The terminal version of Claude Code (the CLI) is the same agent with a text interface. It has a few things the panel doesn't: every slash command, tab completion, a ! shortcut for running shell commands, and easier setup for connecting external tools. Power users tend to end up there.

You are not a power user yet, and the extension is a better teacher: diffs you can see, rewind you can click, screenshots you can drag. Every terminal skill you build this week transfers directly; when the CLI is worth it, it's one install and typing claude in the terminal you already use. Both share the same conversation history, so nothing is lost by starting here. Give it two or three weeks in the panel first.

09First push, first deploy

The deck covers the five Git commands you'll use daily. This section is only the first time, which has one extra step: connecting Vercel. Do it on Day 1, before anything looks good. A live URL that says “hello” is worth more than a perfect site that's still on your laptop.

Your first push

Because you created the repository from the template in Section 05, it already exists on GitHub and your clone is connected to it. Nothing to publish. Prove it, then send up the name change you made in Section 08:

zsh · portfolio
% git remote -v
origin  https://github.com/YOUR-USERNAME/portfolio.git (fetch)
origin  https://github.com/YOUR-USERNAME/portfolio.git (push)
% git add .
% git commit -m "my name and role"
% git push
# first time, VS Code may pop a GitHub sign-in. approve it.

Refresh github.com. Your commit is there. From now on, that's the loop: git add ., git commit -m "…", git push.

Connect Vercel

  1. vercel.com → Add New… → Project.
  2. Find portfolio in the list of your GitHub repos → Import. (First time, it'll ask to install the Vercel app on your GitHub account. Allow it.)
  3. It detects Next.js automatically. Change nothing. Click Deploy.
  4. About a minute later: a URL like portfolio-abc123.vercel.app. Open it on your phone. It's real.

From now on, every git push triggers a new deploy. You'll get an email if a build fails, and the Vercel dashboard shows the same error npm run build would have shown you locally. Which is why you run that first.

The daily loop, end to end

zsh · portfolio
% npm run dev                      # morning. leave it running
  … work with Claude in the panel, look at localhost:3000 …
% npm run build                    # in the second terminal, before pushing
% git add .
% git commit -m "homepage hero and project cards"
% git push                         # vercel deploys. check the url on your phone

10When something breaks

It will. Almost all of it is one of these. Read the first line of any error; the rest is usually noise.

You seeWhat it means · what to do
zsh: command not found: nodeNode isn't installed, or this terminal was opened before you installed it. Quit VS Code fully (⌘Q) and reopen. Still failing → reinstall Node from nodejs.org.
command not found: codeYou skipped the Install 'code' command in PATH step. ⌘⇧P → shell command.
Cannot find module …Packages are missing. Run npm install in the project folder.
Port 3000 is in useA dev server is already running in another terminal. Next.js will just use 3001; either is fine. Or find the other terminal and ⌃C it.
npm ERR! … ENOENT … package.jsonYou're in the wrong folder. Type pwd. cd into portfolio.
EACCES: permission deniedYou tried to install something globally. You don't need to this week. Don't use sudo; ask what you were trying to do.
Red error overlay in the browserA code error in the file you just changed. Copy the first line, paste it to Claude with “fix this,” or click rewind.
Browser shows old contentFile isn't saved (look for a dot on the tab; ⌘S), or the dev server crashed. Check the terminal for red text; restart with npm run dev.
Terminal looks frozenThe dev server is running. That's the job. Open a second terminal (⌃⇧`).
Vercel build failedRun npm run build locally. Same error, easier to read. Fix, push again.

When stuck for more than ten minutes: screenshot the terminal, screenshot the browser, drop both into Claude with “what's wrong and what should I type?” Then text Vinson. In that order.

11Words you'll hear

terminal
The text box where you type commands. The program running inside it on a Mac is called zsh, the “shell.”
command
One line you type and run. npm run dev is a command.
PATH
The list of places your Mac looks for programs when you type their name. “command not found” means it's not on the PATH.
Node.js
Runs JavaScript on your Mac instead of in a browser. Next.js and npm both need it.
npm
Downloads packages into your project. Comes with Node.
npx
Runs a package once without installing it.
package
A chunk of someone else's code you download and use. Also called a dependency.
package.json
Your project's manifest: name, dependencies, scripts.
node_modules
Where downloaded packages live. Huge, ignored by Git, regenerable.
script
A named command in package.json. Run with npm run name.
dev server
The local server that shows your site and reloads on save.
localhost
This computer. localhost:3000 = this computer, door 3000.
build
Compiling your source into the optimized files a real server sends to visitors.
deploy
Putting a build on the internet. Vercel does it on every push.
repo
Short for repository. A project folder tracked by Git, locally or on GitHub.
commit
A named save point in Git.
push
Sending your commits to GitHub.
framework
The structure your site is built inside. Next.js is a framework built on React.
React
The library that lets you build UI out of components. You won't write it; Claude will.
component
A reusable piece of UI. A card, a nav, a button.
route
A URL. In Next.js, a folder in app/ with a page.tsx.
Tailwind
Styling via class names on elements instead of separate CSS files.
TypeScript
JavaScript with type checking. Catches mistakes early. Invisible to you.
CLAUDE.md
A file Claude Code reads at the start of every session. Your project's rules go here.
CLI
Command-line interface: a program you use by typing. The terminal version of Claude Code is “the CLI.”
